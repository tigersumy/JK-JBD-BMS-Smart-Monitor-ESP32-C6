🌐 **Українська версія** | **[English Version](README_EN.md)**

**Універсальний, повністю автономний розумний BLE-шлюз та локальний веб-монітор для акумуляторних батарей (LiFePO4 / Li-ion / LTO) на базі мікроконтролера ESP32-C6 (із підтримкою ESP32-S3).**

Підтримує одночасно 5 провідних протоколів BMS: **JK-BMS (JiKong)**, **JBD-BMS (Jiabaida / Xiaoxiang / Overkill Solar / PowerQueen)**, **Daly Smart BMS**, **Ant BMS** та **Redodo / LiTime Monolithic Smart BMS** із вбудованою функцією автоматичного розпізнавання протоколу (Auto-Detect).

## ⚡ Головні особливості

* 🔄 **Універсальна підтримка 5 протоколів (5-in-1 Universal BMS)**:
  * **JBD-BMS / Xiaoxiang / Overkill Solar / PowerQueen**: робота через BLE Service `0xFF00`, підтримка запитів Basic Info (`0x03`), напруг комірок (`0x04`), імені пристрою (`0x05`), перевірка 16-бітного CRC та керування MOSFET-ключами (`0xE1`).
  * **JK-BMS / JiKong**: робота через BLE Service `0xFFE0`, декодування повного фрейму TLV (~300 байт), аутентифікація по PIN-коду, керування Charge MOS, Discharge MOS та активним балансиром.
  * **Daly Smart BMS**: робота через BLE Service `0xFFF0` (`0xFFF1` Notify / `0xFFF2` Write) та апаратний сервіс `02F00000-...-FE00`, запити телеметрії `0x90`–`0x98` (напруги комірок, струм, SOC, ємність, температури, захисти, балансування), керування ключами Charge/Discharge MOS (`0xDA`, `0xD9`).
  * **Ant BMS**: робота через BLE Service `0xFFE0` (`0xFFE1` Notify / `0xFFE2` Write), NUS або `0xFFF0`, опитування `0xDB 0xDB`, декодування 140-байтного фрейму телеметрії `0xAA 0x55 0xAA 0xFF` (до 32 комірок, струм, потужність, температури MOS/T1/T2, SOC, ємність), керування ключами Charge MOS, Discharge MOS та балансиром (`0xA5 0xA5 ...`).
  * **Redodo / LiTime Monolithic Smart BMS**: робота через BLE Service `0xFFE0` (`0xFFE1` Notify / `0xFFE2` Write), опитування запитом `0x00 0x00 0x04 0x01 0x13 0x55 0xAA 0x17`, декодування 105-байтного фрейму телеметрії `0x00 0x00 0x61 0x01 0x93` (напруга клем, до 16 комірок, струм, температури комірок/MOS/середовища, захисти, балансувальна маска, цикли).
  * **Auto-Detect**: автоматичне розпізнавання підключеного типу BMS за рекламними пакетами та сервісами Bluetooth.

* 🔋 **Повна автономність (100% Standalone)**:
  * Працює на одному мікроконтролері ESP32-C6 / ESP32-S3 без потреби у ПК, Raspberry Pi, Home Assistant чи інверторі.
  * Живлення від будь-якого джерела USB Type-C 5V або DC-DC конвертера.

* 🖥️ **Сучасний Dark SPA Web Dashboard**:
  * Адаптивний інтерфейс для смартфонів, планшетів та десктопів.
  * Двомовність: миттєве перемикання між **українською** та **англійською** мовами (🌐 UA / EN).
  * **Швидкі KPI**: Загальна напруга, струм батареї (з кольоровою індикацією заряд/розряд), активна потужність (W), рівень заряду (SOC%), залишкова та номінальна ємність (Ah), кількість циклів.
  * **Гістограма комірок (4S / 8S / 16S / 24S)**: напруга кожного осередку з роздільною здатністю 1 мВ, автоматичне підсвічування **MIN** та **MAX** осередків, динамічний розрахунок дельти напруг ($\Delta V$).
  * **Керування захистом**: інтерактивні перемикачі MOSFET Заряду (Charge MOS), MOSFET Розряду (Discharge MOS) та Активного Балансира.
  * **Статистика системи**: температури MOSFET та датчиків АКБ, рівень сигналу Wi-Fi RSSI, обсяг вільної оперативної пам'яті (Heap).

* 🌐 **Мережа та налаштування**:
  * Робота у домашній Wi-Fi мережі (Station Mode) + резервна точка доступу `BMS-Monitor-AP` (`192.168.4.1`) з Captive Portal.
  * Локальне mDNS ім'я: **`http://bms-monitor.local`**.
  * Вбудовані сканери Wi-Fi мереж та Bluetooth BMS пристроїв на сторінці налаштувань (`/setup`).

* 🔘 **Апаратне керування кнопкою BOOT (GPIO 9)**:
  * **Короткий клік (< 3 сек)**: примусовий реконнект Bluetooth та оновлення телеметрії.
  * **Довге затискання (> 3 сек)**: скидання налаштувань Wi-Fi та BMS (Factory Reset) та повернення у режим точки доступу `BMS-Monitor-AP`. Налаштування Telegram-бота зберігаються!

* ✈️ **Вбудований клієнт Telegram-бота (Віддалений доступ без Tailscale / Білого IP)** *(нове у v1.4.0)*:
  * **Повна незалежність від Tailscale / VPN**: клієнт бота працює через стандартні вихідні HTTPS-запити до Telegram Bot API (`api.telegram.org:443`). Працює через будь-який NAT, мобільний роутер або Starlink.
  * **Інтерактивні команди та меню**:
    * `/status` — зведена інформація: напруга, струм (+/-), потужність (W), SOC %, залишок Ah, цикли, дисбаланс $\Delta V$, температури, стан ключів та балансира.
    * `/cells` — наочна розкладка напруг по всіх комірках (1–32S), автоматичні маркери мінімуму `Vmin 🔻`, максимуму `Vmax 🔺`, активних балансувальних осередків `⚡` та точний дисбаланс $\Delta V$ у мВ.
    * `/control` — стан ключів та інтерактивні кнопки керування.
    * `/info` — статус системи ESP32-C6 (Uptime, вільний RAM Heap, рівень Wi-Fi сигналу, статус BLE).
  * **Керування ключами BMS з підтвердженням (Safety Confirmation)**:
    * Пряме перемикання **Charge MOS (Заряд)**, **Discharge MOS (Розряд)** та **Балансира** прямо з чату Telegram.
    * Кожна дія вимагає обов'язкового підтвердження в чаті (`⚠️ Ви впевнені? [ТАК] [СКАСУВАТИ]`), що виключає випадкове знеструмлення навантаження чи інвертора.
  * **Проактивні Push-сповіщення при критичних подіях**:
    * 🚨 **Критичний дисбаланс комірок**: $\Delta V > 100\text{ мВ}$ (з автоматичним сповіщенням про нормалізацію при зниженні дельти).
    * 🔥 **Перегрів силових MOSFET або датчиків АКБ**: $T > 55^\circ\text{C}$.
    * 🪫 **Критичний розряд АКБ**: $\text{SOC} \le 10\%$ або напруга будь-якої комірки $< 2.80\text{ В}$.
    * ⚠️ **Втрата зв'язку з BMS**: якщо телеметрія через BLE відсутня понад 45 секунд.
  * **Безпека та авторизація (Whitelist)**:
    * Бот реагує та надсилає сповіщення **тільки** на вказані в налаштуваннях `Telegram User ID` (підтримується декілька адміністраторів через кому: `12345678, 87654321`).
  * **100% Опціональність та збереження пам'яті (NVS Guard)**:
    * За замовчуванням бот вимкнено — нуль споживання пам'яті та ефіру.
    * Якщо токен та User ID збережені, вони **не стираються** при апаратному скиданні кнопкою BOOT. Для повного видалення реквізитів Telegram у веб-інтерфейсі передбачено окрему кнопку.

### 🧩 Модульна реалізація протоколів у `BmsBleClient`:
* **JK-BMS (JiKong)**: Сервіс `0xFFE0` (`0xFFE1` Notify / `0xFFE2` Write), декодування великих TLV-кадрів (~300 байт), аутентифікація PIN, керування регістрами Charge/Discharge MOS та активного балансира.
* **JBD-BMS (Jiabaida / Xiaoxiang / Overkill Solar / PowerQueen)**: Сервіс `0xFF00`, структуровані запити Basic Info (`0x03`), напруг комірок (`0x04`) та імені (`0x05`), сувора валідація CRC-16, зчитування NTC3 (MOSFET) та дати виготовлення, керування MOSFET (`0xE1`).
* **Daly Smart BMS**: Сервіс `0xFFF0` (`0xFFF1`/`0xFFF2`) та апаратний сервіс `02F00000-...-FE00`, опитування команд `0x90`–`0x98`, декодування напруг, струму, температур, захистів та перемикання ключів (`0xDA`, `0xD9`).
* **Ant BMS**: Сервіс `0xFFE0` (`0xFFE1`/`0xFFE2`), NUS `6E400001-...` або `0xFFF0`, опитування `0xDB 0xDB`, декодування 140-байтного кадру `0xAA 0x55 0xAA 0xFF` (до 32 комірок, струм 0.1A, потужність, MOS Temp, T1, T2, ємність), керування ключами та балансиром (`0xA5 0xA5 ...`).
* **Redodo / LiTime Monolithic BMS**: Сервіс `0xFFE0` (`0xFFE1`/`0xFFE2`), опитування `0x00 0x00 0x04 0x01 0x13 0x55 0xAA 0x17`, розкодування 105-байтного фрейму `0x00 0x00 0x61 0x01 0x93` (напруга клем, до 16 комірок, струм у мА, температури, захисти, маска балансування).

## 🧪 Тестування з емулятором (Universal BMS Emulator)

Якщо у вас немає під рукою фізичного акумулятора чи BMS, ви можете повністю протестувати систему за допомогою нашого проєкту [Universal BMS BLE Emulator](https://github.com/tigersumy/JBD-bms-emulator):

1. **Прошийте плату-емулятор** (ESP32-C6 або ESP32) скетчем емулятора.
2. **Виберіть протокол для емуляції**:
   * **Через кнопку BOOT при увімкненні**: затисніть або зробіть подвійний клік кнопки BOOT для перемикання:
     * 🔴 **3 червоних спалахи** = JBD BMS (`JBD-SP04S034`)
     * 🟣 **3 пурпурових спалахи** = Daly Smart BMS (`DL-8S-200A`)
     * 🔵 **3 синіх спалахи** = Ant BMS (`ANT-BMS-08S`)
     * 🟠 **3 помаранчевих спалахи** = JK BMS (`JK-B2A8S20P`)
     * 🟡 **3 жовтих спалахи** = Redodo / LiTime Monolithic BMS (`Redodo-12V100A` / `LT-12100B`)
   * **Через веб-інтерфейс емулятора**: перейдіть на `http://192.168.4.1` (або `http://bms-emulator.local`) та виберіть потрібний профіль зі списку.
3. **Підключення монітора**:
   * Відкрийте сторінку налаштувань монітора `http://192.168.4.1/setup` (або `http://bms-monitor.local/setup`).
   * Натисніть **🔍 Find BMS** — монітор знайде емулятор в ефірі BLE.
   * Клікніть на знайдений пристрій — поле MAC та тип протоколу заповняться автоматично!
   * Натисніть **💾 Save & Connect** та насолоджуйтеся миттєвою живою телеметрією.

### 💡 Приклади керування ключами через `curl`:

```bash
# 1. Увімкнути зарядку (Charge MOS):
curl -X POST http://bms-monitor.local/api/switch \
     -H "Content-Type: application/json" \
     -d '{"switch": "charging", "state": true}'

# 2. Вимкнути розрядку (Discharge MOS):
curl -X POST http://bms-monitor.local/api/switch \
     -H "Content-Type: application/json" \
     -d '{"switch": "discharging", "state": false}'

# 3. Увімкнути активний балансир (для JK-BMS та Ant BMS):
curl -X POST http://bms-monitor.local/api/switch \
     -H "Content-Type: application/json" \
     -d '{"switch": "balancer", "state": true}'
```

## 🏠 Інтеграція в Home Assistant

### Варіант 1: RESTful Sensor (підтримується вже зараз)
Додайте у ваш `configuration.yaml` Home Assistant:

```yaml
sensor:
  - platform: rest
    name: "Home Battery BMS"
    resource: "http://bms-monitor.local/api/data"
    scan_interval: 5
    json_attributes:
      - bms_type
      - connected
      - cell_count
      - cell_voltages
      - delta_cell_v
      - min_cell_v
      - max_cell_v
      - temp_mos
      - temp_sensor1
      - temp_sensor2
      - switch_charging
      - switch_discharging
      - switch_balancer
    value_template: "{{ value_json.total_voltage | round(2) }}"
    unit_of_measurement: "V"

  - platform: template
    sensors:
      battery_current:
        friendly_name: "Battery Current"
        unit_of_measurement: "A"
        value_template: "{{ state_attr('sensor.home_battery_bms', 'current') | default(0) }}"
      battery_soc:
        friendly_name: "Battery SOC"
        unit_of_measurement: "%"
        value_template: "{{ state_attr('sensor.home_battery_bms', 'soc') | default(0) }}"
      battery_power:
        friendly_name: "Battery Power"
        unit_of_measurement: "W"
        value_template: "{{ state_attr('sensor.home_battery_bms', 'power') | default(0) }}"
      battery_delta_v:
        friendly_name: "Cell Delta Voltage"
        unit_of_measurement: "V"
        value_template: "{{ state_attr('sensor.home_battery_bms', 'delta_cell_v') | default(0) }}"
```

### Варіант 2: MQTT Discovery (У планах на v1.4.0) 🚀
У наступному релізі **v1.4.0** заплановано інтеграцію нативного клієнта **Home Assistant MQTT Discovery**:
* Автоматичне виявлення пристрою в Home Assistant через брокер MQTT (`homeassistant/sensor/bms_monitor/.../config`).
* Нульова конфігурація: всі сутності (напруга, струм, SOC, ємність, температури, окремі сенсори напруги комірок 1..32, а також кнопки керування MOSFET) з'являтимуться в HA як єдиний інтегрований пристрій.
* Двостороннє керування ключами Charge/Discharge MOS та балансиром прямо з картки Home Assistant через MQTT топіки команд.

## 🚀 Швидкий старт та Прошивка

### Варіант 1: Прошивка готового бінарника через `esptool`

Підключіть ESP32-C6 по USB та виконайте:

```bash
# 1. Повне очищення Flash (рекомендовано):
esptool.py --port /dev/ttyUSB0 erase_flash

# 2. Завантаження єдиного factory-бінарника (адреса 0x0000):
esptool.py --port /dev/ttyUSB0 --baud 921600 write_flash 0x0000 bin/esp32c6_universal_bms_monitor_factory.bin
```
*(Для macOS замініть `/dev/ttyUSB0` на `/dev/cu.usbmodem...`)*.

---

### Варіант 2: Збірка з вихідного коду (PlatformIO)

```bash
# Компіляція для ESP32-C6:
pio run -e esp32-c6-supermini

# Прошивка на підключену плату:
pio run -e esp32-c6-supermini -t upload

# Монітор Serial порту:
pio device monitor -b 115200
```

*(Для плат на базі ESP32-S3 використовуйте енвайронмент `-e esp32-s3-supermini`)*.

## ⚙️ Перше налаштування пристрою

1. Після першого увімкнення плата створить точку доступу Wi-Fi: **`BMS-Monitor-AP`** (без пароля).
2. Підключіться до неї з телефону або комп'ютера та відкрийте у браузері: **`http://192.168.4.1`**.
3. У формі налаштувань:
   * Виберіть вашу домашню мережу Wi-Fi та введіть пароль.
   * Натисніть **🔍 Find BMS** (або введіть MAC-адресу вручну).
   * Виберіть тип BMS (*Auto Detect*, *JK-BMS*, *JBD-BMS*, *Daly Smart BMS*, *Ant BMS* або *Redodo / LiTime*) та кількість комірок (*4S, 8S, 16S, 24S*).
   * Натисніть **💾 Save & Connect**.
4. Пристрій перезавантажиться, підключиться до вашого Wi-Fi і стане доступним за адресою: **`http://bms-monitor.local`**.

### Крок 3. ⚠️ КРИТИЧНО: Перший запуск бота (Ініціалізація чату)
> [!IMPORTANT]
> **Чому це обов'язково?**  
> За правилами безпеки Telegram, жоден бот **не має технічної можливості першим надіслати повідомлення людині**, поки користувач особисто не ініціює діалог з ботом.  
> Якщо ви вкажете токен та ID у моніторі, але **не натиснете START у боті**, сервер Telegram відхилить тестове повідомлення з помилкою:  
> `Bad Request: chat not found (Користувач ще не натиснув START у чаті з цим ботом)`.

1. Знайдіть вашого щойно створеного бота в пошуку Telegram за його юзернеймом (або перейдіть за прямим посиланням `https://t.me/<username_вашого_бота>`).
2. Натисніть велику кнопку **START** внизу чату (або надішліть текстову команду `/start`).
3. Тепер Telegram зареєстрував ваш діалог, і бот отримав дозвіл надсилати вам повідомлення, графіки та тривоги!

### Крок 5. Команди бота та віддалене керування

У чаті з ботом вам доступні інтерактивні команди та меню з кнопками швидкої відповіді:

| Команда | Опис та результат |
|---|---|
| `/status` | **Повний звіт про поточний стан батареї**: загальна напруга (В), струм із кольоровою індикацією напрямку (🟢 Заряд / 🔴 Розряд / ⚪ Очікування), потужність (W), рівень заряду (SOC %), залишкова ємність (Ah), лічильник циклів, максимальний розбаланс ($\Delta V$ у мВ), температури MOSFET та батареї, поточний стан ключів Charge MOS, Discharge MOS та активного балансира. |
| `/cells` | **Детальна карта напруг усіх осередків (1–32S)**: пономерний список напруг із точністю до 1 мВ, автоматичні візуальні маркери найслабшого осередку (`Vmin 🔻`), найсильнішого (`Vmax 🔺`), позначка комірок під активним балансуванням (`⚡`) та точний підсумок дельти $\Delta V$. |
| `/control` | **Пульт керування MOSFET-ключами та балансиром**: надсилає інтерактивну клавіатуру з кнопками швидкого перемикання захисту. |
| `/info` | **Апаратна діагностика контролера**: час безперервної роботи (Uptime), вільна оперативна пам'ять (Heap RAM), рівень сигналу Wi-Fi RSSI, статус підключення BLE до BMS та версія прошивки. |
| `/help` | Довідка по всіх доступних командах. |

#### 🛡️ Безпечне перемикання ключів (Confirmation Guard)
Щоб уникнути випадкового натискання кнопок у чаті та аварійного знеструмлення вашого інвертора чи навантаження, кожна дія з ключами захищена обов'язковим підтвердженням:

1. При натисканні, наприклад, `[⛔ Вимкнути розряд]` бот надсилає діалог:
   ```text
   ⚠️ УВАГА! Ви дійсно бажаєте ВИМКНУТИ ключ Розряду (Discharge MOS)?
   Це знеструмить вихід батареї!
   [✅ ТАК, ВИМКНУТИ]  [❌ СКАСУВАТИ]
   ```
2. Команда виконується BMS **тільки** після явного натискання `[✅ ТАК]`.
3. При натисканні `[❌ СКАСУВАТИ]` запит миттєво скасовується без змін.

### Крок 6. Автоматичні Push-сповіщення при аваріях (Proactive Alerts)

Якщо увімкнено опцію Push-сповіщень, ESP32-C6 автоматично надсилає термінові сповіщення в Telegram при виникненні будь-якої нештатної ситуації:

* 🚨 **Високий дисбаланс осередків ($\Delta V > 100\text{ мВ}$)**:
  * Бот сповіщає про критичну нерівномірність осередків, вказує точні напруги найвищої та найнижчої комірки.
  * При поверненні дельти в норму ($\Delta V < 80\text{ мВ}$) автоматично надсилається сповіщення про нормалізацію балансу.
* 🔥 **Перегрів силових транзисторів або датчиків АКБ ($T > 55^\circ\text{C}$)**:
  * Негайне сповіщення із зазначенням температури ключів MOSFET або осередків.
* 🪫 **Критичний розряд акумулятора ($\text{SOC} \le 10\%$ або $V_{\text{cell}} < 2.80\text{ В}$)**:
  * Попередження про небезпеку глибокого розряду з відображенням залишку ємності та напруги найслабшої комірки.
* ⚠️ **Втрата зв'язку з BMS через Bluetooth**:
  * Якщо протягом 45 секунд зв'язок із BMS перервано (наприклад, відійшов роз'єм, BMS заснула або виникли радіоперешкоди), бот сповістить про обрив каналу зв'язку.

### Крок 7. Енергонезалежність та захист конфігурації (NVS Guard)

* **Захист від випадкового стирання**:
  * Реквізити Telegram (токен, дозволені ID, статус активації) зберігаються в ізольованому розділі енергонезалежної пам'яті (NVS namespace `bms_tg`).
  * Якщо ви виконуєте скидання налаштувань Wi-Fi або BMS довгим затисканням апаратної кнопки **BOOT** (> 3 сек), **налаштування Telegram-бота залишаються недоторканими**. Вам не доведеться повторно вводити довгий токен!
* **Повне видалення реквізитів**:
  * Якщо ви хочете назавжди стерти токен та ID з пам'яті контролера (наприклад, при передачі пристрою іншій людині), відкрийте веб-інтерфейс `/setup` та натисніть кнопку **[🗑️ Очистити Telegram]**.
